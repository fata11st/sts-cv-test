# Политика работы с данными и таксономия классов (STS)

## 1. Структура каталогов данных

- `test_data/traffic_v5_mini/` — **неизменяемый эталонный исходник** мини-выборки (40 изображений, 30 исходных `.txt`, `classes.txt`), включённый в Git-репозиторий по регламенту задания.
- `data/curated/` — версионируемый текстовый слой проверенной и исправленной разметки (`labels/*.txt`, 40 файлов) и машиночитаемый журнал всех правок (`audit_changelog.json`). Исходные файлы в `test_data/` при этом не затрагиваются.
- `data/raw/` — директория для внешних/полных наборов данных (исключена из Git; хранит только `.gitkeep`). Пайплайн `src.prepare_dataset` поддерживает подключение дополнительных батчей флагом `--extra-input data/raw/<batch_name>`.
- `data/processed/` — генерируемый воспроизводимый датасет в формате Ultralytics YOLO (`images/{train,val,test}`, `labels/{train,val,test}`, `dataset.yaml`, `split_metadata.json`). Исключён из Git и полностью восстанавливается одной командой:
  ```bash
  python -m src.prepare_dataset --input test_data/traffic_v5_mini --output data/processed --seed 42
  ```

## 2. Таксономия классов и правила разметки (Annotation Guidelines)

Схема классов соответствует `test_data/traffic_v5_mini/classes.txt` (0-based индексация, строго фиксированный порядок):

| ID | Класс | Правило отнесения (выведено из анализа эталонных аннотаций STS) |
|---:|---|---|
| `0` | `bicycle` | Велосипеды и грузовые велотележки. Для велосипедиста размечаются **два** пересекающихся бокса: `bicycle` (сам велосипед) + `pedestrian` (человек). |
| `1` | `car` | Легковые автомобили (седаны, хэтчбеки, кроссоверы, внедорожники, минивэны/пассажирские вэны без спецраскраски). |
| `2` | `motorcycle` | Мотоциклы, скутеры, мопеды (для водителя — аналогично `motorcycle` + `pedestrian`). |
| `3` | `bus` | Городские/пригородные автобусы и пассажирские маршрутные микроавтобусы (ГАЗель-маршрутка, пассажирские автобусы). |
| `4` | `truck` | Одиночные коммерческие грузовики и грузовые фургоны (ГАЗель-фургон/тент, самосвал, мусоровоз, коммерческий пикап с кузовом/стойкой). |
| `5` | `lorry` | Крупнотоннажные магистральные автопоезда / седельные тягачи с полуприцепом (фуры). Полуприцеп фуры входит в единый бокс `lorry`. |
| `6` | `trailer` | Автомобильные прицепы (легковые/тентованные прицепы, буксируемые автомобилем) — размечаются отдельным боксом по корпусу прицепа. |
| `7` | `police` | Спецтранспорт полиции / ДПС (характерная цветографическая схема, синяя полоса, проблесковые маячки). |
| `8` | `ambulance` | Автомобили скорой медицинской помощи (белые/жёлтые с красными полосами, крестом, номером `103`/`112`). |
| `9` | `fire_truck` | Пожарные автомобили МЧС (красно-белая раскраска, лестница/спецоборудование). |
| `10` | `pedestrian` | Пешеходы, регулировщики/сотрудники ДПС вне салона, велосипедисты и мотоциклисты. Водители и пассажиры внутри закрытого салона автомобиля **не** размечаются. |

Дополнительные правила качества:
- Трамваи и рельсовый транспорт **не** входят в список из 11 классов и не размечаются.
- Объекты, скрытые под чёрными ROI-масками приватности, не размечаются; боксы обрезаются строго по границам `[0, 1]`.
- После любого экспорта из CVAT обязательно запускается `python -m src.validate_labels --input <dir> --reference-classes test_data/traffic_v5_mini/classes.txt --strict`.

## 3. Стратегия расширения датасета (Data-Centric план)

Поскольку мини-выборка содержит 40 изображений (экстремальный дисбаланс `car:lorry = 501:3`, отсутствие фоновых кадров и примесь 4 наземных фото из COCO), для перехода к production-качеству рекомендуется расширение через `data/raw/`:
1. **Целевые квоты на редкие классы в CCTV-ракурсе**: минимум 200–300 независимых камер/сцен для `lorry`, `bicycle` (с верхнего ракурса!), `trailer`, `motorcycle`, `police`, `ambulance`, `fire_truck`.
2. **Hard Negative Mining**: 5–10% пустых дорожных кадров (разная погода, ночь, блики фар, трамваи, дорожные знаки) для снижения False Positives.
3. **Анти-утечка при масштабировании**: обязательная группировка по `camera_id` + `dHash`/эмбеддингам фона перед сплитованием.
4. **Воспроизводимость**: внешние батчи хранятся вне Git (`data/raw/`), а их контроль версий обеспечивается через `reports/manifest.sha256` и `--extra-input`.
